# Медиа внутри редактора BAEV Studio

Продолжение работы от `0b07757` в `feat/studio-v2`, 4 октября 2026 года.

## Изменения

Выбор изображения или видео больше не требует выходить из кейса ради загрузки. В блоках, обложке и настройках изображения для ссылки открывается одна медиатека: поиск, фильтры типа и категории, загрузка файла и подтверждение выбора. Сначала можно проверить название, формат, разрешение и вес; отмена сохраняет прежний файл в блоке.

Поиск выполняется по всей базе, включая описание, имя файла и теги. Вместо первых 1000 записей в редакторе и первых 250 в медиатеке сервер отдаёт по 36 файлов. Следующие страницы загружаются по кнопке. Запоздавший ответ предыдущего поиска не заменяет текущие результаты; ошибка следующей страницы не удаляет уже загруженные файлы.

Загрузка поддерживает выбор с устройства и перетаскивание одного файла. Показаны фактический прогресс Blob и отдельный этап сохранения записи. При ошибке файл остаётся доступен для повтора. Если Blob уже загружен, а регистрация в Payload не прошла, повтор использует полученный receipt. Загрузка большого файла повторно не запускается. Окно нельзя закрыть во время загрузки; уход со страницы предупреждает об активной загрузке.

Новый файл сразу появляется в выборе и доступен для вставки. Видео не загружаются всеми карточками одновременно; проигрывание доступно в просмотре медиатеки. Для недоступных изображений показано состояние отсутствующего превью. Подпись поверх выбранного медиа теперь читается в тёмной теме.

API `/api/studio/media` требует пользователя с ролью admin/editor и возвращает ответы `private, no-store`. Схема Payload, миграции, публичный рендерер и содержимое рабочих кейсов не менялись. Все проверки с записью выполнялись в отдельной локальной SQLite.

## Проверки

- Production-сборка Next и TypeScript проходят.
- 41 интеграционная проверка в 11 наборах проходит, включая 8 новых проверок доступа, поиска, повторной загрузки и сетевых ошибок.
- ESLint изменённого кода: 0 ошибок; остаются четыре существующих предупреждения зависимостей hooks в VisualCaseBuilder.
- 11 сценариев в Chromium 133 на настоящей production-сборке Next/Payload: вход, пагинация, поиск по тегу за первой страницей, комбинация фильтров, отказ анонимному пользователю, пустой результат, сброс фильтров, отмена, сохранение выбранного файла, повтор после ошибки загрузки, загрузка прямо в блок, сохранность после перезагрузки и управление фокусом.
- Проверены ширины 1440, 1024, 768, 390 и 360 px. Контролы выбора доступны, горизонтального переполнения нет, ошибок JavaScript не найдено.

В тестовой базе были 40 записей медиа с исходными обложками из `framer-cases.json`, затем добавлен файл через интерфейс. Это тестовые записи, не копия production-базы. Production Blob не изменялся: его протокол сверён с установленным адаптером Payload, а повтор регистрации проверен с подменой сетевых ответов. Реальная загрузка в браузере проверена на локальном хранилище Payload. Другие браузеры и весь WCAG этим этапом не проверялись.

Используемый протокол: [Payload Storage Adapters](https://payloadcms.com/docs/upload/storage-adapters), установленный `@payloadcms/storage-vercel-blob@3.90.2`.

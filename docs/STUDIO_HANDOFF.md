# BAEV Studio — состояние работы

Обновлено 4 октября 2026. Рабочая ветка: `feat/studio-v2`. Приложение: `cms/`.

## Обязательные ориентиры

- Простая тёмная Studio, ориентированная на завершение и публикацию кейса.
- Сохранить публичный язык BAEV, редакционную колонку и медиа-холст исходных кейсов.
- Payload остаётся ядром данных, доступа, черновиков и версий. Технический `/admin` не является основным интерфейсом.
- В Studio уже используются Morphicons и Motion; не подменять их новым набором иконок и демонстрационными UI-шаблонами.

## Следующие предметные задачи

- Редактирование rich text сейчас преобразует документ в простой текст и обратно; перед расширением редактора нужно сохранить форматирование существующих документов.
- Каталог кейсов и связи проектов ещё ограничены запросом на 200 записей; медиатека этого ограничения уже не имеет.
- Для одновременного редактирования из нескольких вкладок ещё нет проверки конфликта версий на сервере.

Не создавать тестовые записи в рабочей базе ради QA. Для повторной проверки использовать отдельную SQLite и явно очищенные POSTGRES/Blob env. Секреты и локальные тестовые базы в git не сохранять.
